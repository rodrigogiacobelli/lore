# Run a Doctrine

A doctrine is a design document plus one mission file per worker; it is passive, and you are the one who runs it. Run a
doctrine for a feature, bugfix or change: read its design, plan its missions, and drive them to completion with workers you
brief. Nothing here needs a task tracker; you keep the plan and the status yourself. You need from the user the doctrine id
(for example `feature-implementation`), a description of the change as detailed as possible, and optionally which phases to
include for a trimmed run. If either of the first two is missing, ask.
